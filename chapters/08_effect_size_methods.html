8.1 Influence of scale bounds on SMDs

The plot above assumes normal distributions, which have no minimum or maximum. Real scales do, and this limits which effect sizes are possible. On a bounded scale, the closer a mean is to the end of the scale, the smaller its SD has to be. A large Cohen’s d requires two means that are many SDs apart, but on a bounded scale the means can only move so far apart before one of them is too close to the end of the scale to have the SD that was reported.

The plot below shows this. Set the logical minimum and maximum of the scale, the SD of both conditions in scale units, and Cohen’s d. The two conditions start at the middle of the scale and move apart as d increases, so that their means are always d × SD scale points apart. Each of the two buttons switches between two settings, and is labelled with the setting that clicking it will change to. The first chooses how the conditions move apart: at first the control condition stays in the middle of the scale and only the intervention condition moves, and the alternative is that both conditions move away from the middle by the same amount. The second chooses the direction of the effect: at first the intervention increases scores, so that Cohen’s d is positive, and the alternative is that it decreases them, so that d is negative. Each condition is drawn as a beta distribution, rescaled to the range of the scale, whose parameters are calculated from its mean and SD by the method of moments. The message under the plot says whether the combination you have chosen is possible.

function betaI(x, a, b) {
  // regularised incomplete beta function, by continued fraction
  if (x <= 0) return 0
  if (x >= 1) return 1
  const front = Math.exp(logGamma(a + b) - logGamma(a) - logGamma(b) + a * Math.log(x) + b * Math.log(1 - x))
  const cf = (x, a, b) => {
    let c = 1, d = 1 - (a + b) * x / (a + 1)
    if (Math.abs(d) < 1e-300) d = 1e-300
    d = 1 / d
    let h = d
    for (let m = 1; m < 500; m++) {
      let aa = m * (b - m) * x / ((a + 2 * m - 1) * (a + 2 * m))
      d = 1 + aa * d; if (Math.abs(d) < 1e-300) d = 1e-300
      c = 1 + aa / c; if (Math.abs(c) < 1e-300) c = 1e-300
      d = 1 / d
      h *= d * c
      aa = -(a + m) * (a + b + m) * x / ((a + 2 * m) * (a + 2 * m + 1))
      d = 1 + aa * d; if (Math.abs(d) < 1e-300) d = 1e-300
      c = 1 + aa / c; if (Math.abs(c) < 1e-300) c = 1e-300
      d = 1 / d
      const del = d * c
      h *= del
      if (Math.abs(del - 1) < 1e-14) break
    }
    return h
  }
  return x < (a + 1) / (a + b + 2) ? front * cf(x, a, b) / a : 1 - front * cf(1 - x, b, a) / b
}

The message under the plot distinguishes three situations. The combination is possible with ordinary hump-shaped distributions. Or it is possible only if at least one condition’s scores are piled up against one end of the scale, as happens with floor and ceiling effects; because such a pile is a spike that runs off the top of the plot, it is labelled with the share of that condition’s participants who would have the highest or lowest possible score. Or it is not possible.

The plot treats a combination as not possible once either condition’s scores would have to be split between the two ends of the scale, with most at one end and a few at the other. Strictly, such data could exist. The absolute limit, which applies to any distribution and not only to beta distributions, is that a sample with a given mean on a scale from min to max cannot have a variance greater than (mean − min) × (max − mean), and this is only reached when every score is at one end of the scale or the other. The limit used by the plot is somewhat stricter than this, because data split between the two ends of a scale are not a plausible description of responses to that scale. One consequence is that the plot treats any SD larger than that of scores spread evenly across the whole scale, which is the range divided by √12, as not possible at all.

Try increasing the SD: the larger the SD relative to the range of the scale, the smaller the largest possible d. The largest possible d is also only half as large when the control condition’s mean stays in the middle of the scale, because only the intervention condition’s mean can then move towards the end of the scale. When an article reports a large standardised effect on a bounded scale, it is worth checking whether the reported means and SDs are compatible with the scale at all.

8.2 Statistical distribution of SMD effect sizes

Whether a reported effect size is plausible depends on more than the size of the true effect. The effect size observed in any one study also depends on sampling error, which is larger in small studies, and on how much the true effect varies between studies. The dance of the p-values (Section 4.4.0.1) showed how much the effect size and p-value of a study vary from one sample to the next, even when nothing about the true effect changes. Taken together, these determine the range within which the observed effect size of a single study can be expected to fall.

The plot below shows this range for Cohen’s d from a two-group design, as a function of the total sample size. For each sample size, it simulates 40,000 studies. Each study’s true standardised mean difference is drawn from a normal distribution with mean μ and standard deviation τ (the between-study heterogeneity). The study’s observed d is then drawn from its sampling distribution, with the total sample split equally between the two groups, with the usual correction for small-sample bias applied. The dashed line shows the mean true effect μ, and the bands show the 95%, 99%, and 99.9% prediction intervals: the ranges within which 95%, 99%, and 99.9% of studies’ observed effect sizes fall.

95%, 99%, and 99.9% prediction intervals (darkest to lightest bands) of an observed d.

function simulatePiD(mu, tau, draws = 40000) {
  // quantiles of the observed, bias-corrected Cohen's d of a two-group study, at each of a log-spaced grid of total sample sizes.
  // each simulated study's true SMD, delta, is drawn from N(mu, tau). its observed d is
  // t * 2 / sqrt(N), where t follows a noncentral t distribution with df = N - 2 and ncp = delta * sqrt(N) / 2,
  // multiplied by the small-sample bias correction J = 1 - 3 / (4 * df - 1). a noncentral t is drawn as (Z + ncp) / sqrt(chi-squared / df).
  // the random numbers are seeded and reused at every sample size, so that the result does not change
  // between redraws and the curves are smooth
  const nSeq = [...new Set(d3.range(16).map(i => Math.round(Math.exp(Math.log(20) + i * (Math.log(500) - Math.log(20)) / 15))))]
  return nSeq.map(N => {
    // mulberry32 pseudo-random number generator
    let state = 1
    const uniform = () => {
      state = (state + 0x6D2B79F5) | 0
      let x = Math.imul(state ^ (state >>> 15), 1 | state)
      x = (x + Math.imul(x ^ (x >>> 7), 61 | x)) ^ x
      return ((x ^ (x >>> 14)) >>> 0) / 4294967296
    }
    // standard normal, by the Box-Muller method
    const normal = () => Math.sqrt(-2 * Math.log(1 - uniform())) * Math.cos(2 * Math.PI * uniform())
    // gamma(shape, 1) for shape >= 1, by the Marsaglia-Tsang method. chi-squared(df) is 2 * gamma(df / 2)
    const gamma = shape => {
      const a = shape - 1 / 3, c = 1 / Math.sqrt(9 * a)
      for (;;) {
        const x = normal(), v = (1 + c * x) ** 3
        if (v <= 0) continue
        const u = 1 - uniform()
        if (u < 1 - 0.0331 * x ** 4 || Math.log(u) < 0.5 * x * x + a * (1 - v + Math.log(v))) return a * v
      }
    }
    const df = N - 2, J = 1 - 3 / (4 * df - 1)
    const d = new Float64Array(draws)
    for (let i = 0; i < draws; i++) {
      const delta = mu + tau * normal()
      const t = (normal() + delta * Math.sqrt(N) / 2) / Math.sqrt(2 * gamma(df / 2) / df)
      d[i] = J * t * 2 / Math.sqrt(N)
    }
    d.sort()
    const q = p => d3.quantileSorted(d, p)
    return {n: N, lo999: q(0.0005), lo99: q(0.005), lo95: q(0.025), hi95: q(0.975), hi99: q(0.995), hi999: q(0.9995)}
  })
}

Several things are worth trying:

  • At small sample sizes, the intervals are wide: a study with a total N of 20 can easily observe an effect twice the size of the true effect, or an effect in the opposite direction. Large observed effects in small studies are therefore not surprising on their own.
  • The intervals narrow quickly as the sample size increases. An observed d of 2 or more in a study with several hundred participants falls far outside the 99% interval unless the true effect is itself very large. Increase μ to find out how large the true effect would have to be before such a result became plausible, and consider whether an effect of that size is credible for the phenomenon in question.
  • Increasing the heterogeneity τ widens the intervals at every sample size, including large ones, because it represents real differences between studies’ true effects and not sampling error.

An observed effect size that falls outside the 99% interval for its sample size, under generous assumptions about the true effect and its heterogeneity, is unlikely to have arisen from a correctly calculated result. It is then worth checking for the common errors described below.

8.4 Cohen’s d explorer

The app below lets you build two samples on the same scale: an intervention condition and a control condition. Set the logical minimum and maximum of the scale, and then set the number of observations at each response option in either of two ways. First, you can draw each distribution: click anywhere in a column to set its bar to that height, or hold the mouse button down and drag across the plot to draw the whole histogram in one movement. The vertical axis rescales when you release, so dragging a bar to the top of the plot makes room for larger counts. Second, you can type the exact number of observations for each response option into the boxes under the axis. The scale can have up to 100 points; with more than 25, the boxes are not shown, because the columns are too narrow for them. The estimates below the two conditions update as you go, each with its 95% confidence interval. They are plotted in three groups, each with its own axis: the two means and the difference between them (intervention minus control), the two SDs and the pooled SD, and the standardised mean difference, Cohen’s d. The first two groups are in the units of the scale, whereas d is in standard deviations. The interval for the mean difference uses the t distribution, the interval for the pooled SD uses the chi-squared distribution, and the interval for d uses the noncentral t distribution, as in the worked example in Section 7.1. Try changing only the spread of the two samples while keeping their means the same, to see how much d depends on the standard deviation, and try to find the largest d that the scale allows.

  const tallest = () => d3.max(groups, g => d3.max(scores, s => g.store.get(s) ?? 0))
  const estimatesPlot = html`<div></div>`
  const grey = "#8a8a8a"
  // the estimates are plotted in three subplots, by type, so that each type has its own horizontal axis
  const subplots = [
   {title: "Standardized Mean Difference", names: ["Cohen's d"], unit: "Standardized units", include: [-1, 1]},
    {title: "Means", names: [...groups.map(g => `${g.short} mean`), "Mean difference"], unit: "Scale units", include: [0, 1]},
    {title: "Standard deviations", names: [...groups.map(g => `${g.short} SD`), "Pooled SD"], unit: "Scale units", include: [0, 1]}
  ]
  const update = () => {
    // rows of the estimates subplots: each condition's mean and SD, then the three effect size statistics
    const rows = []
    for (const g of groups) {
      const stats = g.panel.stats()
      g.title.textContent = `${g.label} (n = ${stats.n})`
      const [lower, upper] = meanCi(stats) ?? [stats.mean, stats.mean]
      if (stats.n > 0) rows.push({name: `${g.short} mean`, est: stats.mean, lower, upper, colour: g.colour})
      const [sdLower, sdUpper] = sdCi(stats) ?? [stats.sd, stats.sd]
      if (stats.n > 1) rows.push({name: `${g.short} SD`, est: stats.sd, lower: sdLower, upper: sdUpper, colour: g.colour})
    }
    const a = groups[0].panel.stats(), b = groups[1].panel.stats()
    const df = a.n + b.n - 2
    const pooled = Math.sqrt((a.ss + b.ss) / df)
    if (a.n > 0 && b.n > 0 && df > 0 && pooled > 0) {
      const diff = a.mean - b.mean
      const scale = Math.sqrt(1 / a.n + 1 / b.n)
      const tCrit = tQuantile(0.975, df)
      // Cohen's d: the bounds are the noncentrality parameters under which the observed t would sit at the
      // 97.5th and 2.5th percentiles of the noncentral t distribution, converted from t to d
      const t = diff / (pooled * scale)
      const ncp = p => bisect(x => 1 - nctCdf(t, df, x), p, -10 - 2 * Math.abs(t), 10 + 2 * Math.abs(t))
      rows.push(
        // mean difference: t distribution
        {name: "Mean difference", est: diff, lower: diff - tCrit * pooled * scale, upper: diff + tCrit * pooled * scale, colour: grey},
        // pooled SD: chi-squared distribution
        {name: "Pooled SD", est: pooled, lower: pooled * Math.sqrt(df / chisqQuantile(0.975, df)), upper: pooled * Math.sqrt(df / chisqQuantile(0.025, df)), colour: grey},
        {name: "Cohen's d", est: diff / pooled, lower: ncp(0.025) * scale, upper: ncp(0.975) * scale, colour: grey}
      )
    }
    estimatesPlot.replaceChildren(...estimateSubplots(subplots, rows, width))
  }
  for (const g of groups) {
    g.title = html`<div class="sb-title" style="color: ${g.colour};"></div>`
    g.panel = frequencyPanel(scores, g.store, {tallest, onChange: ({rescaled}) => {
      if (rescaled) groups.forEach(other => { if (other !== g) other.panel.refresh() })
      update()
    }})
    g.panel.style.setProperty("--sb", g.colour)
  }
  dButtons.querySelector(".sb-clear").onclick = () => {
    groups.forEach(g => g.store.clear())
    groups.forEach(g => g.panel.refresh())
    update()
  }
  update()
  return html`<div>
    ${groups.map(g => html`<div>${g.title}${g.panel}</div>`)}
    <div class="sb-title">Estimates with 95% CIs</div>
    ${estimatesPlot}
  </div>`
}

})
function frequencyPanel(scores, store, {onChange = () => {}, tallest} = {}) {
  // a histogram of the counts in store (a Map of score -> count) that can be edited by drawing in the plot or by
  // typing counts under the axis. onChange is called after every edit, with rescaled: true if the vertical axis
  // may have changed. tallest optionally supplies the count that the vertical axis has to fit, for panels that
  // share an axis. the returned element has two extra methods: stats(), and refresh() to redraw after the store
  // has been changed from outside
  const count = s => store.get(s) ?? 0
  const clamp = (x, min, max) => Math.max(min, Math.min(max, x))

  // the plot is built once and then updated in place, so that it is not replaced in the middle of a drag
  const bars = scores.map(() => html`<div class="sb-bar"></div>`)
  const ghosts = scores.map(() => html`<div class="sb-ghost"><span></span></div>`)
  const grid = html`<div></div>`
  const plot = html`<div class="sb-plot">${grid}${scores.map((s, i) => html`<div class="sb-barcol">${ghosts[i]}${bars[i]}</div>`)}</div>`
  const inputs = scores.map(s => html`<input type="number" min="0" step="1" title="Number of observations at ${s}" aria-label="Number of observations at ${s}">`)
  // with more than 25 scale points, the columns are too narrow for the count boxes, so they are left out and
  // only the scale points that are multiples of 5 or 10 are labelled
  const showCounts = scores.length <= 25
  const labelStep = showCounts ? 1 : scores.length <= 50 ? 5 : 10
  const node = html`<div class="sample-builder">
    ${plot}
    <div class="sb-axis">${scores.map(s => html`<span>${s % labelStep === 0 ? s : ""}</span>`)}</div>
    ${showCounts ? html`<div class="sb-counts">${inputs}</div>` : ""}
  </div>`
  node.stats = () => sampleStats(new Map(scores.map(s => [s, count(s)])))

  // top of the vertical axis: a round number with some headroom above the tallest bar
  let yMax
  const rescale = () => {
    yMax = Math.max(10, d3.nice(0, (tallest ? tallest() : d3.max(scores, count)) * 1.25, 5)[1])
    grid.replaceChildren(...d3.ticks(0, yMax, 5).filter(d => d > 0).map(d => html`<div class="sb-gridline" style="bottom: ${d / yMax * 100}%;"><span>${d}</span></div>`))
  }
  const paint = () => {
    scores.forEach((s, i) => {
      bars[i].style.height = `${Math.min(1, count(s) / yMax) * 100}%`
      // leave the box the user is typing in alone
      if (inputs[i] !== document.activeElement) inputs[i].value = count(s)
    })
  }
  node.refresh = () => { rescale(); paint() }

  // drawing: the pointer's column gives the response option and its height gives the count
  const at = e => {
    const r = plot.getBoundingClientRect()
    return {
      i: clamp(Math.floor((e.clientX - r.left) / r.width * scores.length), 0, scores.length - 1),
      k: clamp(Math.round((r.bottom - e.clientY) / r.height * yMax), 0, yMax)
    }
  }
  const showGhost = (cur) => ghosts.forEach((g, i) => {
    g.style.display = cur && i === cur.i ? "block" : "none"
    if (cur && i === cur.i) { g.style.height = `${cur.k / yMax * 100}%`; g.firstChild.textContent = cur.k }
  })
  let last = null
  plot.onpointerdown = e => {
    if (e.button !== 0) return
    e.preventDefault()
    plot.setPointerCapture(e.pointerId)
    last = at(e)
    store.set(scores[last.i], last.k)
    showGhost(last)
    paint()
    onChange({rescaled: false})
  }
  plot.onpointermove = e => {
    const cur = at(e)
    showGhost(cur)
    if (!last) return
    // also set any columns that the pointer skipped over since the last event, interpolating their heights
    const step = Math.sign(cur.i - last.i)
    for (let i = last.i; i !== cur.i; i += step) {
      store.set(scores[i + step], Math.round(last.k + (cur.k - last.k) * (i + step - last.i) / (cur.i - last.i)))
    }
    store.set(scores[cur.i], cur.k)
    last = cur
    paint()
    onChange({rescaled: false})
  }
  plot.onpointerup = plot.onpointercancel = () => {
    if (!last) return
    last = null
    showGhost(null)
    node.refresh()
    onChange({rescaled: true})
  }
  plot.onpointerleave = () => { if (!last) showGhost(null) }

  // typing: exact counts
  inputs.forEach((input, i) => {
    input.oninput = () => {
      store.set(scores[i], clamp(Math.floor(+input.value) || 0, 0, 9999))
      node.refresh()
      onChange({rescaled: true})
    }
    input.onblur = paint
  })

  node.refresh()
  return node
}

function meanCi({n, mean, sd}) {
  // 95% CI for a mean, or null if it cannot be calculated
  if (!(n > 1 && sd > 0)) return null
  const margin = tQuantile(0.975, n - 1) * sd / Math.sqrt(n)
  return [mean - margin, mean + margin]
}

function sdCi({n, sd}) {
  // 95% CI for an SD, or null if it cannot be calculated
  if (!(n > 1 && sd > 0)) return null
  return [sd * Math.sqrt((n - 1) / chisqQuantile(0.975, n - 1)), sd * Math.sqrt((n - 1) / chisqQuantile(0.025, n - 1))]
}

function sampleStats(counts) {
  // counts: Map of score -> number of observations. ss is the sum of squared deviations from the mean,
  // and sd is the sample SD (n - 1 denominator)
  const entries = [...counts]
  const n = d3.sum(entries, ([, k]) => k)
  const mean = d3.sum(entries, ([s, k]) => s * k) / n
  const ss = n > 0 ? d3.sum(entries, ([s, k]) => k * (s - mean) ** 2) : 0
  return {n, mean, ss, sd: Math.sqrt(ss / (n - 1))}
}

function tQuantile(p, df) {
  const cdf = x => x > 0 ? 1 - 0.5 * betaI(df / (df + x * x), df / 2, 0.5) : 0.5 * betaI(df / (df + x * x), df / 2, 0.5)
  return bisect(cdf, p, -1e4, 1e4)
}

function nctCdf(t, df, ncp) {
  // cumulative distribution function of the noncentral t distribution. T = (Z + ncp) / (U / sqrt(df)), where Z is
  // standard normal and U follows a chi distribution, so P(T <= t) is the average of normCdf(t * u / sqrt(df) - ncp)
  // over the distribution of U. the average is calculated by numerical integration (Simpson's rule)
  const logConstant = -(df / 2 - 1) * Math.LN2 - logGamma(df / 2)
  const density = u => u > 0 ? Math.exp((df - 1) * Math.log(u) - u * u / 2 + logConstant) : (df === 1 ? Math.exp(logConstant) : 0)
  const from = Math.max(0, Math.sqrt(df) - 8), to = Math.sqrt(df) + 8, steps = 400, h = (to - from) / steps
  let sum = 0
  for (let i = 0; i <= steps; i++) {
    const u = from + i * h
    sum += (i === 0 || i === steps ? 1 : i % 2 ? 4 : 2) * density(u) * normCdf(t * u / Math.sqrt(df) - ncp)
  }
  return sum * h / 3
}

function chisqQuantile(p, df) {
  return bisect(x => gammaP(df / 2, x / 2), p, 0, df + 20 * Math.sqrt(2 * df) + 50)
}
function bisect(cdf, p, lower, upper) {
  for (let i = 0; i < 100; i++) {
    const mid = (lower + upper) / 2
    if (cdf(mid) < p) lower = mid; else upper = mid
  }
  return (lower + upper) / 2
}
function normCdf(x) {
  // Abramowitz & Stegun 7.1.26
  const t = 1 / (1 + 0.3275911 * Math.abs(x) / Math.SQRT2)
  const erf = 1 - (((((1.061405429 * t - 1.453152027) * t) + 1.421413741) * t - 0.284496736) * t + 0.254829592) * t * Math.exp(-x * x / 2)
  return x >= 0 ? 0.5 * (1 + erf) : 0.5 * (1 - erf)
}
function logGamma(x) {
  // Lanczos approximation
  const c = [76.18009172947146, -86.50532032941677, 24.01409824083091, -1.231739572450155, 0.001208650973866179, -0.000005395239384953]
  let y = x, sum = 1.000000000190015
  for (const cj of c) sum += cj / ++y
  return -(x + 5.5) + (x + 0.5) * Math.log(x + 5.5) + Math.log(2.5066282746310005 * sum / x)
}
function gammaP(a, x) {
  // regularised lower incomplete gamma function: series for small x, continued fraction otherwise
  if (x <= 0) return 0
  const front = Math.exp(-x + a * Math.log(x) - logGamma(a))
  if (x < a + 1) {
    let term = 1 / a, sum = term
    for (let n = 1; n < 500; n++) { term *= x / (a + n); sum += term; if (Math.abs(term) < Math.abs(sum) * 1e-14) break }
    return sum * front
  }
  let b = x + 1 - a, c = 1e300, d = 1 / b, h = d
  for (let i = 1; i < 500; i++) {
    const an = -i * (i - a)
    b += 2
    d = an * d + b; if (Math.abs(d) < 1e-300) d = 1e-300
    c = b + an / c; if (Math.abs(c) < 1e-300) c = 1e-300
    d = 1 / d
    const del = d * c
    h *= del
    if (Math.abs(del - 1) < 1e-14) break
  }
  return 1 - front * h
}
